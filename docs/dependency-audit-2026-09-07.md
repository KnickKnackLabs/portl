# Dependency audit — 2026-09-07

Baseline: `72e7be2dded83babd873b6706b669734aaa2ce60`. The catalog covers all 71 direct dependency declarations, including workspace aliases, optional native bindings, and development dependencies. Registry versions were read from the [official crates.io index](https://github.com/rust-lang/crates.io-index); prereleases and yanked versions are excluded from “latest stable”. The resolved graph was generated by Cargo with the existing Rust 1.93 toolchain and MSRV fallback enabled.

## Changes selected

- Upgrade Iroh/base/relay to 1.1.0, tickets to 1.0.0, and mDNS lookup to 0.5.0. [Iroh's support announcement](https://www.iroh.computer/blog/v1) ends public relay support for 1.0 release candidates on September 30, 2026. [The 1.1 release](https://github.com/n0-computer/iroh/releases/tag/v1.1.0) includes relay reconnect/shutdown fixes, metrics, and rate-limit diagnostics.
- Upgrade russh to 0.63.2. [Recent releases](https://github.com/Eugeny/russh/releases) fix invalid-channel callbacks, unenforced authentication limits, negotiation panics, and channel backpressure. Adapt explicit channel-open replies so TCP/Unix channels are accepted only after Portl grants the remote operation; rejected requests still reject the SSH channel.
- Replace the direct n0-error prerelease requirement with stable 1.0.0; Cargo resolves 1.0.1.
- Refresh semver-compatible registry dependencies. The final graph has 726 packages versus 742 at the baseline and removes the old Quinn stack. Ring remains the selected TLS provider; neither aws-lc crate is present.
- Delete the unused portable-pty and tokio-test workspace declarations.
- Merge Dependabot's tar, cmov, quinn-proto, and serde_with patches together with the h2 fix in [PR #5](https://github.com/KnickKnackLabs/portl/pull/5); close #6–#8 as superseded. The stable Iroh graph subsequently removes Quinn entirely.

## Major releases retained for separate migration

| Area | Decision and reason |
| --- | --- |
| bincode 2 → 3 | Do not upgrade: [bincode's package notice](https://crates.io/crates/bincode) documents retirement; v3 is a compile-error marker. Herdr protocol 19 uses the v2 encoding. A replacement must prove byte compatibility with Herdr before changing this dependency. |
| libghostty-vt pin → 0.2 | Keep the tested source pin. [The release](https://github.com/Uzaaft/libghostty-rs/releases/tag/v0.2.0) changes the native C ABI, raw bindings, static-link defaults, callbacks and device-attribute API. The current pin already has boxed callback storage, and Portl does not call the dirty-state setters affected by the later render-pointer fix. Validate the changed query, rendering and linking contracts in a dedicated native-ABI migration. |
| ed25519-dalek, sha2, hkdf, rand/rand_core, getrandom | Preserve the direct cryptographic API family used for existing keys, tickets and wormhole interoperability. Iroh's own stack advances to stable dalek 3. The direct dalek 2 / rand_core 0.6 pairing remains valid; switching it is an additional API migration, not required for supported Iroh. |
| age | Take compatible 0.11 maintenance releases. [0.12](https://github.com/str4d/rage/releases/tag/v0.12.0) adds recipient types and changes public error/identity APIs. Portl's existing X25519/passphrase identity format does not need those additions. Keep identity-file migration separate. |
| toml, directories, base64, nix | Keep the current configuration, storage-location, codec and Unix descriptor APIs. A major migration should validate existing configuration fixtures and platform-specific identity lookup behavior. |
| bollard | Keep the Docker API integration that passes the real lifecycle smoke test. [0.21](https://github.com/fussybeaver/bollard/releases) changes the model/query and build dependencies; new Docker features are outside this transport/security update. |
| governor, prometheus-client | Keep Portl's rate-limiter and metrics API versions. Upstream releases change their public APIs; the current limiter and exported metrics have regression coverage. |
| zip, zstd | Keep archive API majors and take compatible patches. Portl uses a constrained archive surface; new compression/archive features are not needed by this update. |
| criterion, clap_mangen, ctor | Keep benchmark, manpage and process-startup APIs while taking compatible maintenance releases. Their newer major APIs do not contribute to the transport/security fix. |

These holds keep the update focused on support deadlines, security fixes and compatible maintenance. Future major migrations should be driven by a needed feature or a defect in a code path Portl uses.

## Rollout and compatibility

Upgrade clients, agents and self-hosted relays together when moving off the release candidate. Iroh guarantees wire compatibility within stable v1; its announcement does not extend that guarantee to the old release candidate. Existing endpoint identities, ticket capability rules and Herdr encoding remain unchanged. Review any explicitly configured release-candidate relay URLs: changing the library does not rewrite user configuration. Portl's default relay list comes from the upgraded Iroh release.
